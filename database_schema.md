# Database Schema — Dental Clinic Management System

> **Cross-references:** See [system_architecture.md](./system_architecture.md) for storage layer decisions, [product_requirements.md](./product_requirements.md) for field-level validation rules, [error_handling_and_testing.md](./error_handling_and_testing.md) for data integrity checks.

---

## 1. Overview

### Current Storage (Local)
All data is stored in a single IndexedDB object store called `data` inside the database `DentalClinicDB` (version 2). Each data type is stored as a key-value pair where the key is one of the `STORAGE_KEYS` constants and the value is the entire array or object.

### Target Storage (Hosted / PostgreSQL via Supabase)
The schema section below defines both the **current in-memory object shapes** (what exists today) and the **target relational SQL schema** for the hosted version.

## 3. Data Models

### 3.1 Patient

**Current JS object shape:**
```typescript
interface Patient {
  id: string;          // "PAT-0001" — generated by generatePatientId()
  name: string;        // Full name, required
  contact: string;     // Phone number, required
  dob: string;         // "YYYY-MM-DD", required
  sex: "male" | "female" | "other";  // required
  age: number;         // Calculated from dob on save; re-calculated on update
  address: string;     // required
  notes?: string;      // Patient history / medical notes, optional
  createdAt: string;   // ISO 8601 timestamp, set once on creation, never changed
}
```

**Field constraints:**
| Field | Required | Validation |
|---|---|---|
| `id` | Auto | Format `PAT-XXXX`, sequential, unique |
| `name` | Yes | Non-empty string |
| `contact` | Yes | Non-empty string (no format validation currently) |
| `dob` | Yes | Must be in the past (`age >= 0`) |
| `sex` | Yes | One of `male`, `female`, `other` |
| `age` | Auto | Derived: `floor((today - dob) / 365.25)` (approximate) |
| `address` | Yes | Non-empty string |
| `notes` | No | Free text |
| `createdAt` | Auto | ISO timestamp on creation |

**Target SQL (PostgreSQL):**
```sql
CREATE TABLE patients (
  id            TEXT PRIMARY KEY,            -- "PAT-0001"
  clinic_id     UUID NOT NULL REFERENCES clinics(id) ON DELETE CASCADE,
  name          TEXT NOT NULL,
  contact       TEXT NOT NULL,
  dob           DATE NOT NULL CHECK (dob < CURRENT_DATE),
  sex           TEXT NOT NULL CHECK (sex IN ('male', 'female', 'other')),
  age           SMALLINT GENERATED ALWAYS AS (
                  EXTRACT(YEAR FROM AGE(dob))::SMALLINT
                ) STORED,
  address       TEXT NOT NULL,
  notes         TEXT DEFAULT '',
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_patients_clinic ON patients (clinic_id);
CREATE INDEX idx_patients_name   ON patients (clinic_id, name);
```

### 3.2 Treatment

**Current JS object shape:**
```typescript
interface Treatment {
  id: string;               // UUID (crypto.randomUUID())
  patientId: string;        // References Patient.id
  description: string;      // Treatment name, required
  date: string;             // "YYYY-MM-DD", required
  cost: number;             // ₹, default 0 if not provided
  dentist: string;          // Dentist name, required
  status: "Scheduled" | "In Progress" | "Completed" | "Cancelled";
  nextVisit: string;        // "YYYY-MM-DD" — required when status = "In Progress"
  consent_file_path: string; // Relative path or empty string
  createdAt?: string;       // ISO 8601 timestamp (added in later version; may be undefined on old records)
  // Note: category is NOT stored on the treatment record — it comes from TreatmentMaster lookup
}
```

**Field constraints:**
| Field | Required | Validation |
|---|---|---|
| `id` | Auto | UUID |
| `patientId` | Yes | Must match an existing `Patient.id` |
| `description` | Yes | Non-empty string |
| `date` | Yes | Valid `YYYY-MM-DD` |
| `cost` | No | Number ≥ 0; defaults to 0 if blank |
| `dentist` | Yes | Non-empty string |
| `status` | Yes | One of four valid values |
| `nextVisit` | Conditional | Required when `status === "In Progress"` |
| `consent_file_path` | No | Relative path string or empty |
| `createdAt` | Auto | ISO timestamp on creation (may be absent on legacy records) |

**Target SQL (PostgreSQL):**
```sql
CREATE TABLE treatments (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  clinic_id         UUID NOT NULL REFERENCES clinics(id) ON DELETE CASCADE,
  patient_id        TEXT NOT NULL REFERENCES patients(id) ON DELETE CASCADE,
  description       TEXT NOT NULL,
  category          TEXT,               -- Stored in hosted version for better querying
  treatment_date    DATE NOT NULL,
  cost              NUMERIC(10, 2) NOT NULL DEFAULT 0 CHECK (cost >= 0),
  dentist           TEXT NOT NULL,
  status            TEXT NOT NULL CHECK (status IN ('Scheduled','In Progress','Completed','Cancelled')),
  next_visit        DATE,
  consent_file_path TEXT DEFAULT '',
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW(),

  CONSTRAINT next_visit_required CHECK (
    status != 'In Progress' OR next_visit IS NOT NULL
  )
);

CREATE INDEX idx_treatments_clinic    ON treatments (clinic_id);
CREATE INDEX idx_treatments_patient   ON treatments (patient_id);
CREATE INDEX idx_treatments_date      ON treatments (clinic_id, treatment_date DESC);
CREATE INDEX idx_treatments_dentist   ON treatments (clinic_id, LOWER(dentist));
CREATE INDEX idx_treatments_status    ON treatments (clinic_id, status);
```

### 3.3 Billing Entry

**Current JS object shape:**
```typescript
interface BillingEntry {
  id: string;              // UUID
  patientId: string;       // References Patient.id
  amount: number;          // Cash/card/UPI amount paid (₹, integer)
  paymentMethod: "cash" | "card" | "upi" | "other";
  pointsEarned: number;    // Points earned from this payment
  pointsRedeemed: number;  // Points redeemed on this payment
  rewardValue: number;     // ₹ value of redeemed points
  totalApplied: number;    // amount + rewardValue
  date: string;            // "YYYY-MM-DD"
  outstandingBefore: number; // Outstanding balance before this payment
  outstandingAfter: number;  // Outstanding balance after this payment
  createdAt: string;       // ISO 8601 timestamp
}
```

**Field constraints:**
| Field | Required | Validation |
|---|---|---|
| `id` | Auto | UUID |
| `patientId` | Yes | Must match existing `Patient.id` |
| `amount` | Yes | Integer > 0, must not exceed `outstandingBefore` |
| `paymentMethod` | Yes | One of four valid values |
| `pointsEarned` | Auto | `floor(amount / 100) * 4` |
| `pointsRedeemed` | Auto | 0 or `floor(availablePoints / 4) * 4` (if redeem checked) |
| `rewardValue` | Auto | `pointsRedeemed / 4` (₹) |
| `totalApplied` | Auto | `amount + rewardValue` |
| `outstandingBefore` | Auto | Calculated from treatment costs minus prior payments |
| `outstandingAfter` | Auto | `max(0, outstandingBefore - totalApplied)` |

**Outstanding balance formula (critical):**
```
outstanding = sum(treatment.cost for patient) - sum(billing.totalApplied for patient)
```

**Target SQL (PostgreSQL):**
```sql
CREATE TABLE billing (
  id                UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  clinic_id         UUID NOT NULL REFERENCES clinics(id) ON DELETE CASCADE,
  patient_id        TEXT NOT NULL REFERENCES patients(id) ON DELETE CASCADE,
  amount            INTEGER NOT NULL CHECK (amount > 0),
  payment_method    TEXT NOT NULL CHECK (payment_method IN ('cash','card','upi','other')),
  points_earned     INTEGER NOT NULL DEFAULT 0 CHECK (points_earned >= 0),
  points_redeemed   INTEGER NOT NULL DEFAULT 0 CHECK (points_redeemed >= 0),
  reward_value      NUMERIC(10, 2) NOT NULL DEFAULT 0 CHECK (reward_value >= 0),
  total_applied     NUMERIC(10, 2) NOT NULL GENERATED ALWAYS AS (amount + reward_value) STORED,
  outstanding_before NUMERIC(10, 2) NOT NULL,
  outstanding_after  NUMERIC(10, 2) NOT NULL CHECK (outstanding_after >= 0),
  payment_date      DATE NOT NULL,
  created_at        TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_billing_clinic   ON billing (clinic_id);
CREATE INDEX idx_billing_patient  ON billing (patient_id);
CREATE INDEX idx_billing_date     ON billing (clinic_id, payment_date DESC);
CREATE INDEX idx_billing_method   ON billing (clinic_id, payment_method);
```

### 3.4 Reward Points

**Current JS object shape:**
```typescript
// Stored as a flat object: patientId → total_points
type RewardPoints = Record<string, number>;
// e.g., { "PAT-0001": 120, "PAT-0002": 48 }
```

> **Note:** In the hosted version, reward points should be a derived value from billing records OR stored as a separate `reward_wallets` table to enable audit trail.

**Target SQL (PostgreSQL):**
```sql
CREATE TABLE reward_wallets (
  patient_id    TEXT PRIMARY KEY REFERENCES patients(id) ON DELETE CASCADE,
  clinic_id     UUID NOT NULL REFERENCES clinics(id) ON DELETE CASCADE,
  total_points  INTEGER NOT NULL DEFAULT 0 CHECK (total_points >= 0),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Or derive dynamically via view:
CREATE VIEW reward_wallet_view AS
SELECT
  patient_id,
  clinic_id,
  SUM(points_earned) - SUM(points_redeemed) AS total_points
FROM billing
GROUP BY patient_id, clinic_id;
```

## 4. Entity Relationships

```
clinics (hosted)
  │
  ├── clinic_users (staff members)
  │
  ├── patients
  │     ├── treatments (1:N)
  │     │     └── (consent_file_path → Supabase Storage)
  │     ├── billing (1:N)
  │     └── reward_wallets (1:1)
  │
  └── treatment_master (clinic-specific catalog)
```

**Relationship rules:**
- Deleting a `patient` cascades to all their `treatments`, `billing` records, and `reward_wallets`.
- Deleting a `clinic` cascades to all patients, treatments, billing, treatment_master.
- `treatment_master` rows are NOT linked to individual treatments — the `description` text is copied at the time of treatment creation. This preserves historical treatment names even if master data changes.

## 6. Data Integrity Rules

| Rule | Enforcement |
|---|---|
| Unique patient ID per clinic | DB `UNIQUE(clinic_id, id)` + app `generatePatientId()` |
| Unique treatment name in master | DB `UNIQUE(clinic_id, treatment_name)` + app duplicate check |
| Outstanding can never be negative | `CHECK (outstanding_after >= 0)` |
| Payment cannot exceed outstanding | App-layer validation in `handleBillingSubmit()` |
| `nextVisit` required for In Progress | DB `CHECK` constraint + app-layer validation |
| Cost must be non-negative | DB `CHECK (cost >= 0)` |
| Points must be non-negative | DB `CHECK (total_points >= 0)` |
| Cascading deletes | `ON DELETE CASCADE` on all FK relationships |

## 7. Migration Script Outline (Local → Hosted)

When migrating a clinic's exported JSON to the hosted PostgreSQL database:

```sql
-- 1. Create clinic record
INSERT INTO clinics (name, address, phone, subdomain) VALUES (...);

-- 2. Insert patients (preserve IDs)
INSERT INTO patients (id, clinic_id, name, contact, dob, sex, address, notes, created_at)
SELECT ... FROM json_populate_recordset(null::patients, $json_patients);

-- 3. Insert treatments
INSERT INTO treatments (id, clinic_id, patient_id, description, treatment_date, cost,
                        dentist, status, next_visit, consent_file_path, created_at)
SELECT ... FROM json_populate_recordset(null::treatments, $json_treatments);

-- 4. Insert billing
INSERT INTO billing (id, clinic_id, patient_id, amount, payment_method,
                     points_earned, points_redeemed, reward_value,
                     outstanding_before, outstanding_after, payment_date, created_at)
SELECT ... FROM json_populate_recordset(null::billing, $json_billing);

-- 5. Insert reward wallets
INSERT INTO reward_wallets (patient_id, clinic_id, total_points)
SELECT key, $clinic_id, value::INTEGER
FROM json_each_text($json_rewards);

-- 6. Insert treatment master
INSERT INTO treatment_master (clinic_id, category, treatment_name, default_price, is_active, created_at)
SELECT ... FROM json_populate_recordset(null::treatment_master, $json_treatment_master);
```

## 8. Rewards Calculation Reference

These formulas are implemented in `app.js` and must be preserved exactly in any refactored or hosted version:

```javascript
// Earning points
function calculateEarnedPoints(amount) {
  // ₹100 = 4 points; ₹250 = 8 points (not 10)
  const blocks = Math.floor(amount / POINT_EARN_RATE);  // POINT_EARN_RATE = 100
  return blocks * POINTS_PER_EARN_BLOCK;                // POINTS_PER_EARN_BLOCK = 4
}

// Redeeming points
function calculateRedeemFromPoints(points, maxRupees) {
  const safePoints = Math.max(0, Math.floor(points || 0));
  const maxFromPoints = Math.floor(safePoints / POINTS_PER_REDEEM_RUPEE); // 4 pts = ₹1
  const safeMaxRupees = Math.floor(Math.max(0, maxRupees || 0));
  const rupeesToApply = Math.min(maxFromPoints, safeMaxRupees);
  const pointsToRedeem = rupeesToApply * POINTS_PER_REDEEM_RUPEE;
  return { pointsToRedeem, rupeesToApply };
}

// Net points after transaction
new_points = old_points - pointsRedeemed + earnedPoints;
```
